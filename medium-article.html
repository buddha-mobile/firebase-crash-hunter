I Built an AI Agent That Fixes Firebase Crashes and Raises PRs — Automatically

A step-by-step guide to building a Claude Code agent that watches your Crashlytics data, diagnoses bugs, writes fixes, and opens draft PRs on GitHub. No server needed.

Every Android team has the same Monday morning ritual: open Firebase Crashlytics, stare at the crash list, groan, and start the slow process of finding the file, understanding the bug, writing the fix, creating a branch, and opening a PR.

Most of those crashes? The same five patterns. !! on a nullable value. A toInt() call on a string that turned out to be empty. A popBackStack() called without checking if there's a back stack. Things a junior engineer could fix in three minutes once they found the right line.

So I automated it. The agent runs whenever I want, queries my Crashlytics data via BigQuery, finds the root cause in the codebase, writes the fix, and opens a draft PR — all without me touching a keyboard. I only review the PR before merging.

"If you can describe the fix in a sentence, an AI can write it."

Here's exactly how to build it for your project.

What You'll Build

Firebase Crashlytics — captures crashes from your production app
↓
BigQuery — stores every crash event as a SQL-queryable row
↓
crash_hunter.sh — shell script that queries BigQuery for today's top crashes
↓
Claude Code CLI — reads the crash data, finds the file, diagnoses the bug, writes the fix
↓
GitHub Draft PR — created automatically with full crash context and fix explanation

You trigger it with a single slash command: /crash-hunter. Or /crash-hunter 7 for the last 7 days.

Prerequisites

  • Firebase project with Crashlytics enabled (any Android app)
  • BigQuery export enabled in Firebase (free, takes 30 seconds to turn on)
  • Claude Code CLI — install from claude.ai/code
  • Google Cloud SDK (gcloud + bq CLI)
  • GitHub CLI (gh) — authenticated with your GitHub account
  • A git repository on GitHub
No CLAUDE.md? No problem.

If your project doesn't have a CLAUDE.md rules file, the agent automatically falls back to universal Kotlin/Android best practices. It still works — it just uses its own judgement instead of your team's specific rules.

Step 1 — Enable BigQuery Export in Firebase

1

Open Firebase Console → Project Settings → Integrations

Find the BigQuery card and click Link. Accept the defaults. Firebase will start streaming crash events to a new dataset called firebase_crashlytics in your Google Cloud project.

2

Find your project ID

Terminal
cat android/google-services.json | grep project_id
# → "project_id": "my-firebase-project"

And your Android package name:

cat android/google-services.json | grep package_name
# → "package_name": "com.example.myapp"
3

Verify the table exists

After ~24h (first export takes time), check:

bq ls my-firebase-project:firebase_crashlytics
# Should show: com_example_myapp_ANDROID

Step 2 — Install & Authenticate the Tools

1

Google Cloud SDK

# macOS
brew install --cask google-cloud-sdk

# Linux
curl https://sdk.cloud.google.com | bash

Then authenticate:

gcloud init
gcloud auth application-default login
gcloud auth application-default set-quota-project YOUR_PROJECT_ID
2

GitHub CLI

brew install gh   # macOS
gh auth login
3

Claude Code CLI

npm install -g @anthropic-ai/claude-code
# Then sign in with your Anthropic account
claude

Step 3 — Add the Script to Your Repo

1

Create the scripts directory

mkdir -p .claude/scripts
mkdir -p .claude/commands
2

Download crash_hunter.sh

curl -o .claude/scripts/crash_hunter.sh \
  https://raw.githubusercontent.com/your-org/firebase-crash-hunter/main/crash_hunter.sh

chmod +x .claude/scripts/crash_hunter.sh
3

Create your config file

.crash-hunter (in repo root — add to .gitignore)
FIREBASE_PROJECT_ID=my-firebase-project
ANDROID_PACKAGE_NAME=com.example.myapp

That's all you need for most projects. The script derives the BigQuery table name automatically: com_example_myapp_ANDROID.

4

Add the Claude Code slash command

.claude/commands/crash-hunter.md
Run the Firebase Crashlytics crash hunter agent.

If the user passes a number (e.g. /crash-hunter 7), treat it as
the lookback window in days. Default is 1 day.

Steps:
1. Run `bash .claude/scripts/crash_hunter.sh $ARGUMENTS`
2. Summarize: crashes found, PRs raised, crashes skipped with reasons.
5

Don't forget .gitignore

# Add to .gitignore
.crash-hunter
.claude/scripts/crash_hunter.log

Step 4 — Run It

Open Claude Code in your repo directory and type:

/crash-hunter

Or from the terminal:

bash .claude/scripts/crash_hunter.sh

You'll see live output as Claude queries BigQuery, reads your code, and (if it finds fixable crashes) creates branches and PRs:

How the Agent Decides What to Fix

The most important design decision in this system: the agent only creates a PR when it is 100% confident. If there's any doubt, it skips the crash and logs why.

ClassificationPatternsAction
HIGH — auto-fix !! NPE toInt() crash Uri.parse() no try-catch JSON bad popBackStack enum no UNKNOWN Branch → fix → commit → push → draft PR
LOW — skip Logic bugs OOM Native crashes System library Architecture issues Log reason, move on

This is intentionally conservative. The agent never half-fixes something. A wrong fix on a payment screen is far worse than no fix at all.

What a PR Looks Like

Every auto-generated PR follows the same structure so your team knows exactly what they're reviewing:

## Firebase Crash Fix

| Field      | Value                          |
|------------|-------------------------------|
| Issue ID   | abc123def456                  |
| Count      | 89 crashes                    |
| Last seen  | 2026-10-21 08:43 UTC          |
| App ver.   | 2.4.1                         |
| Fatal      | true                          |

## Exception
java.lang.NullPointerException: currentUser was null

## Blamed Frame
CheckoutScreen.kt:203 — CheckoutScreenKt.CheckoutContent

## Root Cause
state.currentUser!! on line 203 crashes when the user session
expires mid-checkout. The !! asserts non-null but the session
can be cleared by a background token refresh.

## Fix Applied
Replaced !! with ?: return@Column. If currentUser is null during
checkout, the flexible body is silently skipped instead of crashing.

🤖 Auto-generated by Firebase Crash Hunter

Test Mode — No Real Crashes Needed

Don't want to wait for production crashes to test the pipeline? Use --test:

bash .claude/scripts/crash_hunter.sh --test

This injects a synthetic crash payload pointing at a real !! in your codebase (if you have one) and runs the full pipeline — BigQuery query skipped, everything else real. A draft PR is created so you can see exactly what the output looks like.

Tips & Customisation

Add your team's coding rules

Create a CLAUDE.md file in your repo root with your stack's conventions — forbidden patterns, naming rules, architecture constraints. The agent reads this before touching any code and will apply your rules to every fix. See Claude Code docs for the format.

Widen the lookback window during incidents

/crash-hunter 7   # last 7 days
/crash-hunter 30  # last 30 days

iOS support

The script queries the Android table by default. For iOS, add a second config and run separately:

# .crash-hunter-ios
FIREBASE_PROJECT_ID=my-firebase-project
ANDROID_PACKAGE_NAME=com.example.myapp  # iOS bundle ID uses same format
BQ_TABLE=com_example_myapp_IOS

CRASH_HUNTER_CONFIG=.crash-hunter-ios bash .claude/scripts/crash_hunter.sh

Schedule it (optional)

On macOS, create a LaunchAgent to run it every morning at 09:00 automatically. The repo includes a .plist template.

Limitations (Be Honest With Your Team)

What this won't fix

Logic bugs, OOM errors, ANRs caused by slow startup code, crashes in third-party libraries, device-specific native crashes, or anything that requires understanding your business domain. The agent is designed to skip these rather than guess.

In practice, maybe 20–30% of crashes in a mature app are the mechanical patterns the agent can confidently fix. The rest need a human. But that 20–30% adds up — it's the long tail of !! operators that sneaked through review, the toInt() calls on user input that nobody thought to guard.

The real value isn't replacing engineers. It's eliminating the boring part: finding the file, writing the obvious fix, creating the branch, filling in the PR description.
